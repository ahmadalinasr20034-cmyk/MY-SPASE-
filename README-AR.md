# مساحتي — نسخة PWA محلية، إصدار 2.1

هذه حزمة تطبيق ويب قابل للتثبيت، وليست ملف Windows EXE أو Android APK. لم تُنشر تلقائياً. شكل الأقسام والألوان مبني على ملفك الأصلي، مع فصل CSS وJavaScript وإضافة أدوات الأمان والبيانات.

## تثبيت التطبيق

1. فك ضغط الحزمة.
2. ارفع **محتويات المجلد** معاً إلى مستودع GitHub الذي يحتوي index.html، وليس index.html وحده. لا ترفع نسخ بياناتك JSON.
3. من Settings → Pages اختر main و / (root) ثم Save. هذه الاستضافة توفر HTTPS اللازم لتثبيت PWA؛ التثبيت يأتي من الملفات الجديدة.
4. افتح رابط التطبيق بعد اكتمال البناء. من Chrome أو Edge اختر «تثبيت التطبيق» (أو زر «تثبيت مساحتي» عندما يتيحه المتصفح). على iPhone: Safari → مشاركة → إضافة إلى الشاشة الرئيسية.
5. افتح التطبيق مرة مع الإنترنت وانتظر اكتمال تحميله؛ بعدها جرّب إغلاقه وفتحه دون إنترنت.

للتجربة المحلية على جهاز يحتوي Python: شغّل `python -m http.server 8000` داخل المجلد، ثم افتح http://localhost:8000. فتح index.html بالنقر المزدوج لا يفعّل تثبيت PWA أو العامل المسؤول عن العمل دون إنترنت.

## نقل البيانات القديمة

بياناتك الفعلية في متصفحك، وليست مضمّنة في ملف HTML المرفوع. قبل الانتقال، افتح النسخة القديمة واضغط النسخة الاحتياطية الكاملة ثم انسخ JSON واحفظه بملف. في النسخة الجديدة استخدم «الأمان والبيانات» → «استيراد ملف JSON». يُقبل تنسيق النسخة الكاملة القديم version 1 والجديد version 2. النسخ الجزئية لا تُستورد كنسخ كاملة.

عند فتح النسخة الجديدة **على نفس عنوان الموقع والمتصفح** يجري نقل مفاتيح الأقسام القديمة إلى IndexedDB مع نقطة استرجاع. الانتقال من ملف محلي إلى رابط جديد، أو بين متصفحين، يحتاج تصدير واستيراد.

## ما تغيّر

- تنزيل JSON كامل للأقسام الأربعة، مع رقم إصدار وتاريخ؛ لا يتغير تاريخ التنزيل عند فتح النافذة.
- IndexedDB، حفظ مؤجل، حالة حفظ، نسخة استرجاع قبل الترحيل والاستيراد، واستيراد الأقسام ضمن معاملة واحدة.
- منع استبدال نسخة أحدث باستخدام رقم مراجعة وفحص داخل معاملة التخزين. عند التعارض يمكن تنزيل النسخة المحلية أو تحميل الأحدث أو اعتماد المحلية مع حفظ النسختين كنقاط استرجاع.
- فحص بنية النسخ والمعرّفات وبعض العلاقات والأرقام؛ خيار دمج يحافظ على العنصر الحالي عند تطابق المعرّف. النسخة الأصلية المستوردة لا تعدّل.
- سلة للروايات والفصول والكتب والأفكار واليوميات المحذوفة بعد الحفظ، وأرشفة الكورسات مع جلساتها وبطاقاتها. استرجاع الفصل يحتاج وجود روايته أولاً.
- كلمات الفصل تُحسب من النص؛ حقله اليدوي مقفول عندما يوجد نص. الهدف اليومي يحسب الزيادات الموجبة في عدد الكلمات عند التحرير، وليس مقدار النص الجديد الدقيق؛ تبديل نص بنص بنفس الطول لا يزيده. الحذف لا ينقص النشاط.
- نسخ سابقة للفصل عند بدء التحرير ثم بفاصل دقيقة أثناء الكتابة، وتنزيل الرواية TXT بالعربية.
- مؤقّت دراسة مع إيقاف مؤقت واستئناف ومراجعة الدقائق قبل الحفظ؛ الجلسة تُسجّل بتاريخ بدايتها. عند إعادة فتح التطبيق تكون الجلسة موقوفة مؤقتاً، وتحتاج مراجعة الوقت. قفل المؤقّت بين التبويبات يتطلب Web Locks.
- المزاج الغالب حسب يوميات آخر 30 يوماً غير الفارغة (كل يومية صوت مستقل). الرسم عدد يوميات لكل يوم، وعنوانه يشرح ذلك.
- الحفاظ على تثبيت أسعار الصرف وسجل دفعات الديون الموجودين؛ منع تخفيض أصل الدين تحت الدفعات، وتحسين بعض إدخالات الصفر والتاريخ والأرقام.
- تشفير اختياري لكل قاعدة البيانات بـ AES-GCM ومفتاح مشتق بـ PBKDF2، وقفل بعد 5 دقائق خمول. بعد نجاح التشفير تُحذف نسخ الأقسام القديمة غير المشفرة من localStorage. كلمة المرور لا تُخزّن. نسيانها يمنع فتح البيانات المشفرة؛ التصدير JSON مكشوف بوضوح.
- ملفات PWA وأيقونات وذاكرة تخزين للملفات الأساسية، وزر لتطبيق تحديث جاهز بعد الحفظ. الخطوط الخارجية لها بدائل نظام للعمل دون إنترنت.
- معرّفات DOM فريدة، تسميات وصول إضافية، دعم تقليل الحركة، وتمرير الجداول.

## حدود هذه النسخة وما لم يُنجز بالكامل

- البند 20 (الحسابات، استعادة الحساب، المزامنة، صلاحيات قاعدة بيانات للمستخدمين) **غير منفذ**؛ يحتاج اختيار وإعداد خدمة خلفية. لا يوجد تسجيل دخول وهمي.
- لم تتحول الحسابات المالية كلها إلى نموذج كسور عشرية ثابتة الدقة؛ ما زالت تستعمل JavaScript Number، لذلك لا تعتبر هذه النسخة نظام محاسبة معتمداً. لا يوجد دعم دفع جزئي للمصروف: علامة المدفوع تعني دفعه بالكامل.
- لا توجد مطابقة تلقائية بين مصروف يدوي ودفعة دين يدوية متشابهة؛ لا تسجّل القسط نفسه في المكانين.
- مفاتيح الأشهر القديمة بقيت بأسمائها للحفاظ على البيانات، مع فرزها عبر تاريخ الفترة، ولم تُستبدل جميعها بمعرّفات YYYY-MM.
- فصلت ملفات التنسيق والتشغيل والتخزين، لكن لم أعد كتابة كل الواجهة إلى مكوّنات مستقلة أو أزل جميع قواعد CSS القديمة؛ ولم أجرِ اختبار ضغط للنصوص الكبيرة أو قياس أداء شامل.
- تغيّر التبويب الخارجي من دون تعديلات معلقة يحمّل الصفحة من جديد. الحفظ عند إغلاق النافذة محاولة إضافية؛ انتظر «تم الحفظ» قبل الإغلاق.
- الفحص الآلي المحلي نجح في تشغيل الواجهة والمحرر والعدادات والنسخة الكاملة والرفض الأولي للملفات التالفة والحفظ. لم يتوفر Chromium في بيئة العمل وفشل تنزيله؛ لذلك لم أتحقق بصرياً من التثبيت أو من إعادة الفتح دون إنترنت على متصفح حقيقي. اختبرهما على جهازك قبل الاعتماد اليومي.
- النسخ السابقة وسلة المحذوفات محفوظة حتى تحذفها؛ مع البيانات الكبيرة يزيد حجم قاعدة البيانات. صدّر نسخة خارج التطبيق دورياً.


## تعديلات الإصدار 2.1

- **كلمة المرور**: صارت تُكتب في نافذة بحقول مخفية (نقاط) بدل نافذة المتصفح العادية، مع رسالة داخل النافذة إذا كانت قصيرة (أقل من 10 أحرف) أو إذا اختلف التأكيد. ينطبق هذا على التفعيل وعلى فتح البيانات المشفّرة.
- **استيراد بلصق النص**: زر جديد «استيراد بلصق النص» في «الأمان والبيانات»، مفيد على الموبايل. يمر بنفس الفحص والتأكيد ونسخة ما قبل الاستيراد.
- **إصلاح نسخ قديمة جزئية**: النسخة القديمة لا تحتوي إلا الأقسام التي فيها بيانات. كان الاستيراد يرفضها برسالة «النسخة ناقصة». الآن تُستورد الأقسام الموجودة، وتبقى الأقسام غير الموجودة كما هي بدون مسح.
- **أيقونة جديدة** تمثل الأقسام الأربعة.
- **ترقية ذاكرة الملفات** إلى masahati-v2.1.0: بعد رفع الملفات يظهر زر «تحديث جاهز» عند فتح التطبيق.

الرفع: استبدل الملفات المعدّلة فقط (store.js وsw.js وicon-192.png وicon-512.png)، أو ارفع المجلد كاملاً. لا ترفع ملفات النسخ الاحتياطية.

بعد تغيير الأيقونة: قد يحتفظ نظام الموبايل بالأيقونة القديمة. احذف التطبيق المثبّت وثبّته من جديد لتظهر الجديدة.
